# No Authentication Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A core with no authentication and no HTTP server, whose libraries can be pinned, favorited and renamed, and
which answers catalog totals.

**Architecture:**
- Delete `alexandria-http` and the parity suite first, so the rest only touches the core and the FFI.
- Strip the `AuthService` generic and the `token` argument from every handler and FFI call.
- Delete the auth module, its settings and its tables.
- Add the pin, favorite, rename and statistics commands on the libraries module, each with its FFI function.

**Tech Stack:**
- Rust workspace with `alexandria-core` (sqlx + SQLite, tokio) and `alexandria-ffi` (C ABI, cbindgen header at
  `crates/alexandria-ffi/src/header.h`, generated by `build.rs`).

**Spec:** `docs/superpowers/specs/2026-11-21-no-authentication-design.md`

## Global Constraints

- Branch `feature/no-authentication` (already holds the design commits). Open the pull request into `develop`.
- **Commits:**
  - lowercase Conventional Commits, a subject of at most 50 characters in the imperative, a body wrapped at 72;
  - no attribution lines.
- **Tests:**
  - write the failing test first;
  - Given-When-Then names (`given_..._when_..._then_...`), as the crates already do.
- **Running checks:**
  - this machine lacks ffmpeg's development libraries, so builds and tests run through
    `ci-check lint-and-test ~/repositories/alexandria-api` (clippy, fmt and the tests, in CI's image);
  - `cargo fmt` runs locally;
  - one heavy suite at a time.
- **Code 2 is retired in every FFI result family** (`*_ERR_UNAUTHORIZED`). No other code changes its value.
- **Migrations 0–29 are not edited.** The new migration is `00000000000030_no_authentication.sql`.
- **`Settings` keeps no `deny_unknown_fields`:** an old `config.toml` with `[auth]`/`[http]` still loads.
- **Library JSON field names:** `pinned`, `favorite`.
- **Statistics JSON:** `{"libraries": n, "filesByType": {<every FileType::as_str()>: n}}`.
- `yggdrasil.yml` and `Jenkinsfile` must not change. If one has to, stop and tell the owner, because such a PR is
  theirs to merge.

## Review Focus

1. **A catalog upgraded from 0.6 with a credential row, sessions and recovery codes.** The migration succeeds, and
   every library, file and run is still there. Task 3 pins it.
2. **A `config.toml` written for 0.6 with `[auth] mode = "windows"` and an `[http]` table.** Init still succeeds.
   Task 3 pins it.
3. **Renaming a library whose run is in progress.** The rename succeeds, and the run keeps going and still reports
   the library. Task 5 pins it.
4. **Statistics where a file is soft-deleted, or marked missing.** The counts match what `alexandria_files_list`
   would list. Task 6 pins it.
5. **A pin, favorite or rename on a malformed or unknown UUID.** Answers `INVALID_INPUT` or `NOT_FOUND`, and never
   `OTHER` or a panic. Tasks 4 and 5 pin it.
